# カスタマーグロース事業部 評価制度

営業（AIテレアポ事業部）の Dig 制度をベースに、カスタマーグロース（以下 CG）向けの
評価対象と Dig の生まれ方を定義する。**確定した運用値を反映済み**（粗利率50% / チャーンの扱い /
分配率 / インセン還元率5%）。

---

## 1. 考え方

営業と CG で「Dig の作り方」を揃える。

| | 営業 | CG |
| --- | --- | --- |
| 予算Dig | （役職ベース × 保険係数 × 按分 ＋ 座席代）× 予算係数4.0 | **同じ** |
| 成果Dig の源泉 | 新規契約の**初回契約期間の粗利** | **新たに生まれた粗利**（更新・アップセル） |
| 守りの評価 | — | **チャーン（解約による粗利の喪失）** |

予算Dig の算定式は営業と完全に同一（コストの4倍）。**変えるのは成果Dig の作り方だけ**。

### なぜ「新たに生まれた粗利」なのか
現行設計では、営業の評価数字は「初回契約期間分の粗利」で確定している。
つまり**その期間の粗利は営業に配り切っている**。
2年目更新・アップセルで生まれる粗利は、**その時点では誰にも配られていない**。
ここを CG の原資にすれば、二重計上にならず、契約の生涯価値を漏れなく評価できる。

```
契約の粗利
├─ 初回契約期間（例 1年目）      → 営業へ配分（現行どおり）
├─ 2年目以降の更新期間           → CG へ配分（＋初回営業へ一部）  ← 新設
└─ アップセル（追加回線・コール） → CG へ配分（＋初回営業へ一部）  ← 新設
```

---

## 2. 成果Dig の算定

### 2-1. 共通の考え方

```
成果Dig = 新たに生まれた粗利 × Dig転換率 × 分配率
```

- **新たに生まれた粗利** … 更新・アップセルで増えた売上 × 粗利率
- **Dig転換率** … 粗利をどれだけ Dig にするか。営業と揃えるなら 100%
- **分配率** … CG と初回営業で分ける割合（下記 2-4）

### 2-2. アップセル（追加回線数・コール数）

追加された分の**契約期間ぶんの粗利**を原資にする。

```
アップセル粗利 = (追加回線数 × 回線単価 + 追加コール数 × コール単価) × 粗利率 × 残契約月数
```

| パラメータ | 確定値 | 備考 |
| --- | --- | --- |
| 回線単価・コール単価 | 契約の実額 | 契約管理DBの明細から |
| 粗利率 | **50%** | 全商材共通（商材別に変えたくなったら設定化） |
| 残契約月数 | アップセル日〜契約満了 | 上限は設けない（要見直しなら設定化） |

> **例**: 回線を3本追加（1本5万円）、粗利率50%、残10ヶ月
> 15万円 × 50% × 10ヶ月 = **75万円** → Dig転換率100%なら 75万Dig が原資

### 2-3. 更新（2年目以降）

更新が確定した時点で、**更新期間ぶんの粗利**を原資にする。

```
更新粗利 = 月額 × 粗利率 × 更新期間（月）
```

> **例**: 月額30万円、粗利率50%、12ヶ月更新
> 30万 × 50% × 12 = **180万円** → 180万Dig が原資

初回契約期間と重ならないため、営業の評価数字とは競合しない。

### 2-4. 初回営業への分配

「最初にアカウントを開いた営業」にも分配する。**同じ原資を割る**（原資は増やさない）。

| 発生事由 | CG | 初回営業 | 考え方 |
| --- | --- | --- | --- |
| アップセル | **70%** | **30%** | 関係構築の土台は営業の功績 |
| 更新 | **80%** | **20%** | 運用品質の寄与が大きい |

> **例（アップセル75万Dig）**: CG 52.5万Dig / 初回営業 22.5万Dig

- 分配率は設定で変更できるようにする
- 初回営業が**退職済み**の場合は CG 100%（または事業部プールへ）
- 分配は Dig申請の「折半」と同じ仕組みで実装できる（既存機能を流用）

### 2-5. チャーン（解約）

**更新月での解約（契約期間の満了に伴う終了）はマイナスなし。途中解約のみマイナス計上する。**

| ケース | Dig |
| --- | --- |
| 更新月での解約（満了） | **0**（マイナスなし） |
| 途中解約 | **残存期間の粗利をマイナス計上。CG と初回営業で折半** |

```
途中解約Dig = − ( 月額 × 粗利率50% × 残契約月数 )
負担         = CG 50% : 初回営業 50%
```

> **例**: 月額30万・残8ヶ月で途中解約 → 30万 × 50% × 8 = **▲120万Dig**
> → CG ▲60万Dig / 初回営業 ▲60万Dig

満了での終了は CG の責任範囲外（顧客都合・事業判断）とみなし、途中解約だけを守りの評価に反映する。
**チャーンは CG だけの責任にしない。** 初回に受注した営業にも同じだけ負担してもらう。
初回営業が退職済みの場合は分配率0として CG が全額負う。

## 3. 予算Dig（営業と同一）

```
予算Dig = （役職ベース × 保険係数1.2 × 按分 ＋ 座席代）× 予算係数4.0
```

- 役職ベースは給与レンジ表（役職 × A/B/C）から自動判定
- アルバイトは「実労働時間 × 時給」
- 予算係数・保険係数・座席代は「Dig獲得ルール」タブの**事業部別 Dig予算設定**で持つ。
  CG に値を入れれば CG だけ変えられる（未入力なら上位組織 → 全社既定を継承）

### 達成率の見え方（イメージ）

| 項目 | 金額 |
| --- | --- |
| 予算Dig（コスト×4） | 400万 |
| アップセル（CG分） | +52.5万 |
| 更新（CG分） | +144万 |
| 途中解約 | ▲120万 |
| **実績Dig** | **76.5万** |
| 達成率 | 19% |

---

## 3-2. インセンティブ（営業と異なる）

**営業は 20% 還元、CG は「達成から上振れた分の 5% 還元」。**

```
インセンティブ = max(成果Dig − 予算Dig, 0) × 5%
```

> **例**: 予算400万・成果500万 → 上振れ100万 × 5% = **5万**

**ボーナスDig（行動指標）は還元原資に含めない。** 借入Dig も同様に除外する。
残高（持ち越し）にはボーナスDig を積むが、還元金の計算には上振れ分だけを使う。
これは営業・CG 共通のルール。

還元率は「Dig獲得ルール」タブの事業部別設定（および従業員マスタの組織設定）にある
「インセン還元率」で持つ。未設定なら上位組織を引き継ぎ、どこにも無ければ既定20%。
**カスタマーグロース事業部に 5 を設定する**。

## 4. 実装に必要なもの

### 4-1. いま無いデータ

| 必要なもの | 現状 | 対応 |
| --- | --- | --- |
| **途中解約フラグ・解約日** | **実装済み** | 契約管理DBのフラグを日次同期で取込み、未処理アラートを出す |
| **粗利率** | 無し | 商材（modelKey）ごとに設定として持つ |
| **更新履歴** | 無し | 契約管理DBに更新日・更新期間が必要 |
| **アップセル履歴** | 無し | 契約明細の増減差分、または契約管理DB側で記録 |
| **初回担当営業** | SP_CRM の担当者 | 契約に「初回営業」を固定保持する |

**契約管理DBへの依頼事項が増える。** 既に依頼予定の `division` / `lines` / `calls` に加えて、
`updated_at`（更新日）・`renewal_term`（更新期間）があると更新・アップセルも自動化できる。

### 4-1-2. 途中解約フラグの運用（実装済み）

契約管理DB側で途中解約フラグを立てると、以下が自動で回る。

1. 毎日 5:00（JST）の同期で `earlyCancel` / `canceledOn` を取込む
2. 「Dig獲得ルール」タブの**途中解約アラート**に未処理として出る（タブにバッジ）
3. 管理者が金額を確認して**確定**するまでアラートは消えない
4. 入力欄には `月額 × 粗利率50% × 残契約月数` の計算値が初期表示される（上書き可）

フラグの列名は `early_cancel_flag` / `early_cancel` / `is_early_cancel` / `mid_term_cancel` /
`churn_flag` / `途中解約フラグ` を自動で拾う。別名にする場合は環境変数
`CONTRACT_EARLY_CANCEL_COLUMN` で列名を指定する。解約日は `canceled_on` / `canceled_at` /
`cancel_date` / `cancelled_on` / `解約日` を拾う。

### 4-2. 算定ルールの型（実装済み）

`CalcRuleType` に次の3種別を追加済み。粗利率と分配率はルールごとのパラメータとして持つ。

| 種別 | 算定 | 既定 |
| --- | --- | --- |
| `アップセル粗利` | 増分月額 × 粗利率 × 残月数 → CG と初回営業で分ける | 粗利率50% / 営業30% |
| `更新粗利` | 月額 × 粗利率 × 更新月数 → CG と初回営業で分ける | 粗利率50% / 営業20% |
| `チャーン損失` | 月額 × 粗利率 × 残月数 × −1 → CG と初回営業で分担 | 粗利率50% / 営業50% |

デプロイ時に `R-CG-UPSELL` / `R-CG-RENEWAL` / `R-CG-CHURN` の3ルールが
「カスタマーグロース事業部」で自動登録される。事業部名が違う場合は画面から編集する。

### 4-3. どこで確認・変更するか

すべて **「Dig獲得ルール」タブ**にまとまっている。事業部フィルタで CG を選べば CG の分だけ表示される。

| 見たいもの | 場所 |
| --- | --- |
| 制度サマリ（予算式・成果Digの作り方・インセン・昇降級） | タブ上部の事業部カード |
| 予算係数・保険係数・座席代・昇降級しきい値・インセン還元率 | 事業部別 Dig予算設定 |
| アップセル / 更新 / チャーンの粗利率・分配率 | Dig獲得ルール一覧（種別で表示が変わる） |
| 途中解約の未処理 | 途中解約アラート |

### 4-4. 段階的な進め方

| 段階 | 内容 | 状態 |
| --- | --- | --- |
| **1** | ルール種別（アップセル/更新/チャーン）と粗利率・分配率をルールとして登録 | **実装済み** |
| **2** | 途中解約を契約管理DBから自動取込＋アラート | **実装済み** |
| **3** | 更新・アップセルも契約管理DBから自動取込 | 契約管理DBの列追加待ち |

段階3までは、更新・アップセルは Dig申請フォームからの手入力で運用する。
金額は上表の式で計算し、折半機能で初回営業へ分配する。

## 5. 確定した運用値

| 項目 | 確定値 |
| --- | --- |
| 粗利率 | **50%**（全商材共通） |
| チャーン | **更新月での解約はマイナスなし / 途中解約は残存粗利をマイナス計上** |
| 分配率（アップセル） | **CG 70 : 営業 30** |
| 分配率（更新） | **CG 80 : 営業 20** |
| 負担率（チャーン） | **CG 50 : 営業 50**（折半） |
| インセンティブ還元率 | **上振れ分の 5%**（営業は20%） |
| インセンの原資 | **上振れ分のみ**（ボーナスDig・借入Digは含めない／営業・CG共通） |
| Dig転換率 | 粗利 1円 = 1Dig（千円切捨） |
| アップセルの評価期間 | 残契約期間の全額（上限なし） |
| 初回営業が退職済み | CG 100%（分配率0%として扱う） |

### 未確定（運用しながら決める）
- チャーンのマイナスに下限を設けるか（例: 単月予算の −50% まで）
- 商材ごとに粗利率を変えるか
